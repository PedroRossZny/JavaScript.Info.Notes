# The "new Function" Syntax

## Exercise 249

There is another rarely used way to create a function, following this syntax:
`let func = new Function ([arg1, arg2, ...argN], functionBody)`. The function is created
with the arguments `arg1...argN` and the provided `functionBody`. The function may or may
not have arguments.

Its main difference is that it is created from a string passed at runtime, allowing any
string to be turned into a function. We can receive a new function from a server and then
execute it. This is used in specific cases such as receiving code from a server or
compiling a function from a template in complex web applications, as shown in **ex249**.

## Exercise 250

A regular function remembers where it was born. `new Function` does not remember the
local environment where it was created — it works from the global environment and
receives data through parameters.

The code of this type of function is not known at script writing time, but at runtime —
we can receive it from a server or another source. Before JavaScript goes to production,
it is compacted using a *minifier*, a program that reduces code size by removing extra
comments and spaces, and renaming local variables to shorter names. For example,
`let userName` might become `let a`. This is safe because nothing outside the function
can access the variable and the minifier replaces all mentions of it. Minifiers are smart
and do not break anything.

If `new Function` had access to outer variables, it would not be able to find the renamed
ones — and beyond that, it would be architecturally bad code, prone to errors. This is
why to pass something to a function created with `new Function`, we must use its
arguments, as shown in **ex250**.

## Additional

Arguments can be provided as a comma-separated list. The three declarations below mean
the same thing:

```js
new Function('a', 'b', 'return a + b'); // basic syntax
new Function('a,b', 'return a + b'); // comma-separated
new Function('a , b', 'return a + b'); // comma-separated with spaces
```
