# The Old "var"

## Exercise 238

This is useful knowledge for understanding older code — we do not write code this way
today. `var` is similar to `let` and can be swapped with it, but internally `var` is
different and has very old origins. Understanding the differences is important when
migrating old scripts from `var` to `let` to avoid unexpected errors, as shown in
**ex238**.

## Exercise 239

`var` variables have function scope or global scope — they are visible across blocks.
Since `var` ignores code blocks, it becomes a global variable, applying to blocks like
`if` and loops alike. If the code block is inside a function, it becomes a function-level
variable. `var` passes through `if`, `for`, and other code blocks because in the early
days of JavaScript, blocks did not have Lexical Environments — `var` is a remnant of
that, as shown in **ex239**.

## Exercise 240

Declaring the same `let` variable twice results in an error. With `var` however, we can
declare a variable as many times as we want — if `var` is used with an already declared
variable, the declaration is simply ignored, as shown in **ex240**.

## Exercise 241

`var` declarations are processed when the function or script starts. They are defined
from the beginning of the function regardless of where they appear in the code — code
blocks are ignored. This behavior is called *hoisting*, because all `var` declarations
are lifted to the top of the function.

This applies to declarations only, not assignments. A declaration is processed at the
start of the function, but the assignment always works where it appears. Since all
declarations are processed at the start, we can reference them anywhere, but the
variables remain `undefined` until they are assigned, as shown in **ex241**.

## Exercise 242

Since only `var` existed before and it had no block-level visibility, a way to emulate it
was invented called *Immediately Invoked Function Expressions*, or IIFE. We do not use
this today, but we may encounter it in old scripts.

A function expression is created and called immediately, giving the code its own private
variables. The function is wrapped in parentheses `(function {...})` because when the
engine encounters `function` in the main code, it interprets it as the start of a
function declaration, which would need a name — resulting in an error. Even with a name
it would not work, since function declarations cannot be called immediately in JavaScript.

The parentheses around the function are a trick to show JavaScript that the function was
created in the context of another expression — making it a function expression, which
does not need a name and can be called immediately. There are other ways to achieve the
same result as well, as shown in **ex242**.
