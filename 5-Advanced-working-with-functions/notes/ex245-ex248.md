# Function Object, NFE

## Exercise 245

In JavaScript, functions are objects — they are like action objects that can be called.
We can choose not to call them and instead treat them as objects: adding or removing
properties, passing them by reference, and so on. Function objects have some built-in
properties, such as `name`. Name assignment is smart — it correctly assigns a name to a
function even if it was created without one and immediately assigned to a variable. It
also works when the assignment is made through a default value. This feature is called a
*contextual name* — if the function does not provide one, it is inferred from the context
during assignment. Object methods also have names. There are cases where the correct name
cannot be determined, in which case the `name` property is empty — but in practice most
functions have a name, as shown in **ex245**.

## Exercise 246

There is another built-in property called `length`, which returns the number of parameters
a function has. Rest parameters are not counted. It is used for introspection in functions
that operate on other functions.

For example, a function that accepts a question and an arbitrary number of handler
functions — when the user gives an answer, it calls the handlers: one without arguments,
called only if the user gives a positive answer, and one with arguments, called in both
cases and receiving the answer. To do this we analyze the `length` of each handler,
allowing a simple syntax for handlers with no arguments for positive cases, while also
supporting universal handlers. This is a case of *polymorphism* — treating arguments
based on their type, in this case depending on `length`, as shown in **ex246**.

## Exercise 247

We can also add our own properties to a function, such as a call counter. A property is
not a variable — we can treat a function as an object and store properties in it, but
this has no effect on its execution. Variables are not function properties — they are
parallel worlds.

Function properties can replace closures. The difference is that if a value lives in an
outer variable, external code cannot access it — only nested functions can modify it.
But if it is bound to a function as a property, external access is possible. Choosing
between closures and function properties depends on our goals, as shown in **ex247**.

## Exercise 248

Named Function Expression (NFE) is the term for function expressions that have a name.
Adding a name does not turn it into a function declaration — it is still part of an
assignment expression, so no problems arise. The name allows the function to reference
itself internally, and it is not visible outside the function.

This is useful because if we use the outer variable name to call the function internally
and that variable changes in external code — the function being assigned to another
variable — errors will occur. This happens because the function looks up its name in the
outer Lexical Environment, where the variable may no longer hold the function. The
optional internal name solves this problem since it is local to the function itself —
a *function internal name*. This feature exists only for function expressions, not
function declarations, since declarations have no syntax for adding an internal name, as
shown in **ex248**.

## Additional

Because functions can contain additional properties, many well-known JavaScript libraries
make great use of this feature — creating a main function and attaching several helper
functions to it. Libraries like *jQuery* with its `$` function and *lodash* with `_` do
this to reduce global namespace pollution. A single library provides one global variable,
reducing the chance of naming conflicts. This way a function can do useful work on its
own while also carrying a set of additional functionality in its properties.
