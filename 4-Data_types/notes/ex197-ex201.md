# WeakMap and WeakSet

## Exercise 197

JavaScript keeps a value in memory as long as it is reachable. For example, if we put an
object inside an array and then overwrite the variable that referenced that object, the
object will still remain in memory because the array holds a reference to it. The same
happens if we use a `Map` with the object as a key — the object will remain in memory as
long as the `Map` exists, as shown in **ex197**.

---

## Exercise 198

`WeakMap` is different from `Map` in that it does not prevent an object from being garbage
collected when its reference no longer exists. Additionally, its keys must be objects —
primitive values are not allowed. `WeakMap` does not support iteration or the methods
`keys()`, `values()`, and `entries()`, making it impossible to retrieve all keys or
values. It only has the following methods: `weakMap.set(key, value)`, `weakMap.get(key)`,
`weakMap.delete(key)`, and `weakMap.has(key)`, as shown in **ex198**.

---

## Exercise 199

`WeakMap` is mainly used to store additional data. If we want to store data related to an
object from another codebase or a third-party library, and that data should only exist
while the object is alive, `WeakMap` is the right choice. For example, in a code that
keeps track of user visit counts — when a user is removed, their count will also be
removed from memory automatically since everything is stored inside a `WeakMap`, as shown
in **ex199**.

---

## Exercise 200

Another use case can be seen in **ex200**, where we cache the results of a function so
that future calls with the same object reuse the cached result. In this scenario, using a
regular `Map`, we cannot clear the cache when the object is no longer needed. With
`WeakMap` however, the cache is automatically removed from memory as soon as the object
itself is removed.

## Exercise 201

`WeakSet` is similar: it is analogous to `Set`, but we can only add objects to it, not
primitive values. An object exists in the set as long as it is reachable from somewhere
else. Like `Set`, it supports `add`, `has`, and `delete`, but not `size`, `keys()`, or
any iteration. It can also serve as additional storage, but not for arbitrary data — only
for yes or no answers. We could use `WeakSet` to track who has visited our site, for
example.

The most notable limitation of `WeakMap` and `WeakSet` is the absence of iteration and
the inability to retrieve all current content. This may seem like a drawback, but they
fulfill their main purpose of being additional data storage for objects that are managed
or stored elsewhere, as shown in **ex201**.
