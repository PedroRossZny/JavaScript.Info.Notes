# Date and Time

## Exercise 211

The built-in `Date` object stores date and time, and provides methods to manage them. It
can store creation or modification times, measure elapsed time, or print the current date.
To create a `Date` object, call `new Date()` with one of the following arguments:

- `new Date()` — no arguments, creates a `Date` for the current date and time.
- `new Date(milliseconds)` — creates a `Date` with a time equal to the number of
milliseconds elapsed since January 1st, 1970. The integer representing the number of
milliseconds elapsed since the start of 1970 is called a *timestamp*. We can create a
date from a timestamp using `new Date(timestamp)` and convert an existing object to a
timestamp using `date.getTime()`. Dates before 01/01/1970 have negative timestamps.
- `new Date(datestring)` — if there is only one argument and it is a string, it is parsed
automatically.
- `new Date(year, month, date, hours, minutes, seconds, ms)` — creates a date with the
given components in the local timezone. Only the first two arguments are required. The
`year` should have 4 digits — 2 digits also work, where `98` is treated as `1998`, but 4
digits are recommended. The `month` starts at `0` for January and goes to `11` for
December. The `date` is the day of the month — if absent, the first day is assumed. If
`hours/minutes/seconds/ms` are absent, they are assumed to be `0`.

## Exercise 212

There are methods to access the year, month, and so on from a `Date` object:

- `getFullYear()` — gets the year in 4 digits.
- `getMonth()` — gets the month, from 0 to 11.
- `getDate()` — gets the day of the month, from 1 to 31.
- `getHours()` / `getMinutes()` / `getSeconds()` / `getMilliseconds()` — get the
corresponding time components.

Many JavaScript engines implement the non-standard `getYear()` method, but it is
deprecated and sometimes returns a two-digit year — never use it, always use
`getFullYear()` instead.

We can also get the day of the week with `getDay()`, which goes from `0` for Sunday to
`6` for Saturday. All the methods above return components relative to the local timezone.

There are also UTC counterparts that return the day, month, year, and so on for the UTC+0
timezone: `getUTCFullYear()` / `getUTCMonth()` / `getUTCDay()` — just insert `"UTC"`
right after `"get"`.

There are also special methods without a UTC variant:

- `getTime()` — returns the timestamp, the number of milliseconds elapsed since January
1st, 1970 UTC+0.
- `getTimezoneOffset()` — returns the difference between UTC and the local timezone, in
minutes.

- `setFullYear(year, [month], [date])`
- `setMonth(month, [date])`
- `setDate(date)`

- `setMinutes(min, [sec], [ms])`
- `setSeconds(sec, [ms])`
- `setMilliseconds(ms)`

## Exercise 214

The *autocorrection* feature of `Date` means that if we set out-of-range values, the
object adjusts itself automatically. For example, if we need to add 2 days to February
28th, 2016, the result could be March 1st or 2nd depending on whether it is a leap year.
With autocorrection we do not need to worry about that — just add 2 days and the date
adjusts accordingly. This feature is commonly used to get a date after a certain period
of time. We can also set zero or negative values, as shown in **ex214**.

## Exercise 217

If we want a reliable performance benchmark for CPU-intensive functions, we need to be
careful. Comparing two functions that do the same thing — one using the explicit
`date.getTime()` and the other relying on date-to-number conversion — the explicit one is
faster since there is no type conversion, making it easier for engines to optimize.

These performance measurements are called *benchmarks*. For a more reliable comparison in
a modern multiprocessor operating system, the entire test suite should be run multiple
times. In JavaScript, modern engines start applying optimizations only to hot code that
is executed many times — there is no need to optimize rarely executed parts. Therefore
the first executions are not well optimized, which is why we add a *heat-up run* before
measuring, as shown in **ex217**.

## Exercise 218

The method `Date.parse(str)` can read a date from a string. The string format must be:
`YYYY-MM-DDTHH:mm:ss.sssZ`, where:

- `YYYY-MM-DD` — the date: year-month-day.
- `"T"` — used as a delimiter.
- `HH:mm:ss.sss` — the time: hours, minutes, seconds, and milliseconds.
- The optional `'Z'` indicates the timezone in the format `+-hh:mm`. A single letter `Z`
means UTC+0.

Shorter variants are also possible, such as `YYYY-MM-DD`, `YYYY-MM`, or even `YYYY`. The
method parses the string and returns the timestamp — if the format is invalid, it returns
`NaN`. We can also create a `new Date` directly from the timestamp, as shown in
**ex218**.

## Exercise 219

JavaScript does not have a built-in way to measure time in microseconds, but most
environments provide this functionality. Browsers have the `performance.now()` method,
which returns the number of milliseconds since the page started loading with microsecond
precision (3 digits after the decimal point). Node.js has the `microtime` module and
other alternatives. Almost any device or environment allows for greater precision — it is
simply not available through the `Date` object, as shown in **ex219**.
